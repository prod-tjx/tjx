LESSON 01

Pandas as the glue between Snowflake and the rest of the world

MODULES 2 & 3

Course Material

The Pandas + NumPy modules taught the everyday DataFrame operations I now reach for constantly:

  • concat — stack results from multiple queries
  • drop_duplicates — collapse overlapping rows
  • reset_index — clean handoff to writers
  • groupby — aggregate by category
  • Boolean masks for fast filtering

How I Applied It

The trader hunting pipeline runs N pattern SQLs against a temp frame, each returning a DataFrame. I needed to merge them into one canonical result without double-counting orders that hit multiple patterns.

Course-taught pattern: collect into a list, pd.concat, then dedupe on a stable key (order_identifier), then ship to Snowflake via write_pandas.

Result

One source-of-truth table per run, no duplicate orders across overlapping patterns, clean handoff to the downstream AutoCT executor.

~15 patterns → 1 deduped table 0 duplicate order IDs
trader_hunting_queries_to_table.py — main loop
Python
# Run each pattern, collect non-empty DataFrames
all_results = []
for path in sql_files:
    pattern = pattern_name_from_path(path)
    qtype   = read_query_type_override(sql_text) or infer_query_type(pattern)
    inner   = extract_select_from_ddl(sql_text)

    df, n = execute_pattern(pattern, qtype, inner)
    pattern_metrics[pattern] = {"count": n, "type": qtype}
    if not df.empty:
        all_results.append(df)

# Concat → dedupe → write — three lines that replaced ~50 lines of SQL UNION logic
combined = pd.concat(all_results, ignore_index=True)
pre = len(combined)
combined = combined.drop_duplicates(subset=["order_identifier"], keep="first")
print(f"Dedup: {pre:,} → {len(combined):,} unique orders")

LESSON 02

Programming best practices: small functions, config at the top, paths from __file__

MODULE 6

Course Material

  • Separation of concerns — one function, one job
  • Config at the top — magic strings hoisted to constants
  • Defensive defaults — argparse, env-var fallbacks
  • CWD-independence — resolve paths from __file__ so the script runs anywhere
  • Docstrings as the first thing future-you reads

How I Applied It

Decomposed the pipeline into single-purpose helpers: extract_select_from_ddl, execute_pattern, write_results, format_slack, create_temp_frame.

Hoisted every table name, role, and path into a config block. Resolved active_queries/ relative to the script so it runs identically in Jenkins, PyCharm, or local CLI — no more "works on my machine."

Result

New hunting patterns are added by dropping a .sql file into active_queries/. Zero Python changes. Zero deploys. Zero PRs to the pipeline itself.

+1 pattern = +1 file 0 code review needed

LESSON 03

Automation in production: secrets, batching, idempotency, observability

MODULE 7

Course Material

  • Jenkins-friendly entrypoints with argparse
  • Secrets via env vars, never in code
  • Structured logging with timestamps + levels
  • Batching large API calls to avoid timeouts
  • Empty-result guards for idempotent reruns
  • Fail loudly, succeed quietly (or notify on success only)

How I Applied It

The AutoCT executor pulls the TH backlog, generates an A3 token from an APP_PASSWORD Jenkins secret binding, then batches ACM TRADERCONFIRM calls in chunks of 500.

Posts a green-bar Slack summary only on successful action, silent on empty backlog, raises on failure.

Empty-result guard on the backlog query prevents a column-metadata crash when Snowflake returns 0 rows.

Result

Hands-off trader confirms running on a Jenkins schedule. Per-pattern case notes make every single action auditable in ACM.

Up to 500 orders / batch 0 manual touches per run 100% auditable case notes

# 3. Batch large API calls — ACM has a per-request ceiling
def batch_confirm(env, dsid, token, identifiers, case_note, batch_size=500):
    n       = len(identifiers)
    batches = math.ceil(n / batch_size)
    items   = list(identifiers.items())
    for i in range(batches):
        chunk = dict(items[i*batch_size : min((i+1)*batch_size, n)])
        log.info("Batch %d/%d (%d orders)", i+1, batches, len(chunk))
        parse_response(confirm_orders(env, dsid, token, chunk, case_note))

# 4. Per-pattern case notes — every action is auditable in ACM
for pattern, group in df.groupby("HUNTING_PATTERN"):
    case_note   = f'SDS Trader Confirm SL TH - "{pattern}"'
    identifiers = {oid: case_note for oid in group["ORDER_ID"]}
    batch_confirm(args.env, args.dsid, token, identifiers, case_note)
