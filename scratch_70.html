LIGHTNING TALK · WHAT I LEARNED FROM PYTHON

From writing a script
to shipping a system.

Three habits from the TFA Python Accelerator that turned a notebook into a production pipeline.

LESSON 01

Data is the input to action, not the output.

Pandas stopped being a way to inspect a table and became the glue layer between SQL and the next step in the pipeline. Combine, dedupe, write back, move on.

pd.concat drop_duplicates write_pandas
combine_and_clean.py
# Stack every query result, keep each order once, write it back.
combined = pd.concat(all_results)
combined = combined.drop_duplicates(subset=["order_id"])
write_to_snowflake(combined)
LESSON 02

Adding a feature should change one file, not the system.

Config at the top, one function per job, paths resolved from the script itself. The result: a new hunting pattern is a single SQL file dropped into a folder. No Python edits. No deploy.

config block one function, one job SCRIPT_DIR paths
main.py
# main() reads like a table of contents.
def main():
    setup_tables()
    run_all_queries()
    save_results()
    send_slack_update()
LESSON 03

Production code assumes no one is watching.

Secrets come from the environment. Big jobs run in batches. Empty results exit cleanly. Slack speaks only when there is something to say, and failures fail loudly. The script earns the right to run unattended.

env over hard code batches of 500 loud on failure
autoct_executor.py
# Fail fast if the secret is missing. Never let prod run silently broken.
password = os.environ.get("APP_PASSWORD")
if not password:
    raise RuntimeError("APP_PASSWORD not set")

# Batch the work. Speak only when there is something to say.
for batch in chunks(orders, size=500):
    confirm_orders(batch)

if total_actioned > 0:
    post_to_slack(f"Confirmed {total_actioned} orders")

The biggest shift.

I used to write Python to get an answer once. Now I write Python to build something that keeps working without me. The difference is not the language. It is the habits.
