Capstone FY26 · TFA Trader

Problem Statement

The Trader team had no automated path to decisioning. Throughput was capped by headcount, volume was driven by upstream programs, and high-accuracy detection patterns sat unleveraged.
🧑‍💻
Capacity Constraint
(Headcount-Capped Throughput)
Every trader-flagged order required individual analyst review. Throughput was directly tied to FTE count, with no path to scale volume without adding headcount.
📈
Cross-Program Impact
(Upstream Spikes Land on D68)
When teams like AMP and ASO Fraud action at scale on FA2 and DGF blocks, the resulting queue cascades onto D68 trader blocks. Volume drivers sat outside the team's control.
🛠️
Tooling Leverage
(Proven Queries, Manual Execution)
TFAs had already written hunting queries with 99%+ accuracy. Those insights existed, but had no operational path beyond an analyst manually running them. Proven patterns sat idle.
The Underlying Opportunity
Operationalize What Already Works
All three problems converge on the same gap. The team had proven detection patterns but no way to run them autonomously. Building tooling to consolidate analyst-developed queries into an automated decisioning pipeline does three things at once: it frees headcount from manual review, creates a defensive mechanism against upstream volume spikes, and unlocks the value of high-accuracy insights that had been sitting in analyst hands. The work was not in inventing new detection logic. It was in extending an existing process with the tooling needed to scale it.
