LESSON 01

Use Pandas to combine and clean data from many sources

MODULES 2 & 3

What the course taught

Pandas gives you a spreadsheet you can control with code. The key moves:

  • concat — stack tables on top of each other
  • drop_duplicates — remove repeated rows
  • groupby — group rows by a column
  • Filtering with simple true/false rules

How I used it

The pipeline is built to run 15+ different SQL queries, each looking for a different type of suspicious order. Today, 2 patterns are live and more are queued up to add.

I stack all the results into one big table, drop any order that appears in more than one query, and save the clean list back to Snowflake.

What it produced

One clean table of unique orders, ready for the next step in the pipeline to act on.

Built for 15+ queries 2 patterns live today 0 duplicate orders
Combining results from many queries into one clean table
Python
# Start with an empty list to collect results from every query
all_results = []

# Loop through each .sql file in the active_queries folder
for query in sql_files:

    # Run the query against Snowflake — returns a Pandas DataFrame
    # (a DataFrame is basically a table with rows and columns)
    df = run_query(query)

    # Skip queries that found nothing — no point keeping empty tables
    if not df.empty:
        all_results.append(df)

# Stack every result on top of each other into one big table
# Example: query A finds 100 orders, query B finds 50 → combined has 150 rows
combined = pd.concat(all_results)

# Remove any order_id that appears more than once
# (an order might be flagged by 2+ patterns — we only want it listed once)
combined = combined.drop_duplicates(subset=["order_id"])

# Write the final clean table back to Snowflake for the next step to use
write_to_snowflake(combined)
LESSON 02

Write code other people (and future-you) can actually read

MODULE 6

What the course taught

  • One function = one job — small pieces, not giant blocks
  • Put settings at the top — change in one place
  • Don't hard-code file paths — let the script find them automatically
  • Write a clear summary at the top of every file

How I used it

I broke my pipeline into small named pieces, each doing one thing: read the SQL, run it, clean the results, save them, send the Slack update.

All the table names and settings live in a single block at the top, so anyone can update them without hunting through the code.

What it produced

Adding a new fraud pattern is now a one-file change: drop a SQL file into the folder. No Python changes. No code review of the pipeline itself.

+1 pattern = +1 file 0 deploys needed
BEFORE
v0.1
# File paths break when run from a different folder
QUERY_DIR = "./active_queries"

# Same table name typed 9 times — easy to mistype
run_query("INSERT INTO long.table.name ...")
run_query("TRUNCATE long.table.name ...")

# One huge function doing everything
def main():
    # 300 lines of mixed logic...
    ...
AFTER
v1.0
# Script finds its own folder — runs anywhere
QUERY_DIR = os.path.join(SCRIPT_DIR, "active_queries")

# Names defined once, used everywhere
RESULTS_TABLE = "my_schema.results"
LOGGING_TABLE = "my_schema.log"

# main() reads like a table of contents
def main():
    setup_tables()
    run_all_queries()
    save_results()
    send_slack_update()
LESSON 03

Make your script safe to run on a schedule, with no one watching

MODULE 7

What the course taught

  • Keep passwords out of code — read them from the environment
  • Split big jobs into batches so they don't time out
  • Handle the "nothing to do" case without crashing
  • Notify on success, stay quiet on empty, fail loudly on errors

How I used it

My AutoCT script runs on Jenkins every few hours. It pulls the password from a Jenkins secret, asks ACM to confirm orders in chunks of 500, and posts a green Slack message only when it actually does something.

If there's no work to do, it stays silent. If something breaks, it raises a clear error.

What it produced

A hands-off job that confirms suspicious orders automatically, with a full audit trail in ACM for every action.

500 orders / batch 0 manual clicks Every action traceable
Four habits from Module 7, all in one script
Python
# 1. Read the password from the environment, never the code
password = os.environ.get("APP_PASSWORD")
if not password:
    raise RuntimeError("APP_PASSWORD not set")

# 2. Handle the empty case gracefully
if df.empty:
    log.info("Nothing to do — exiting")
    return

# 3. Process in batches so we don't hit API limits
for batch in chunks(orders, size=500):
    confirm_orders(batch)

# 4. Tell Slack only when we actually did something
if total_actioned > 0:
    post_to_slack(f"Confirmed {total_actioned} orders")
